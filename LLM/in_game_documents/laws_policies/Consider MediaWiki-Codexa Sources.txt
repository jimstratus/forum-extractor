ChatGPT said:
Great question — here's how they compare from Codexa’s perspective:
🧾 Google Docs (Current System)
Pros:
    Supports structured tables (like the current registry format)
    Easy to parse tabular data (e.g., “Status”, “Title”, “Last Modified”)
    Maintains formatting and column order reliably
    Good for admin editing/version control
Cons:
    Requires manual re-indexing unless paired with API polling
    Slower to scale across large content categories
    Fragmented navigation if content is across many docs
🌐 MediaWiki (Proposed)
Pros:
    Pages are URL-addressable and semantically structured
    Can easily scrape, index, and parse category/tag-based pages
    Built for canonical knowledge (great for lore databases)
    Supports metadata, version history, and discussions inline
    Supports APIs for live indexing and search (if enabled)
Cons:
    Less table-friendly unless using dedicated templates
    May require consistent formatting rules (e.g., "status: canonical" lines) for proper parsing
    Edits may be less visually accessible to non-wiki editors (compared to Google Sheets)
🔍 Codexa’s Preference
If the registry is refactored for MediaWiki with consistent metadata structure (e.g.,:
== Title ==
Status: Canonical  
Category: Policy  
Last Updated: 2025-03-27  
), then MediaWiki is the better long-term system for automated, real-time parsing, and scale.
    ✅ Yes, it’s easier (and more powerful) for me to read from a well-structured wiki page than a Google Doc — as long as page formatting is clean and consistent.
